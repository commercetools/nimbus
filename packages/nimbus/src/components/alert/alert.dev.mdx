## Getting started

### Import

```tsx
import { Alert, type AlertProps } from '@commercetools/nimbus';
```

### Basic usage

The Alert component uses a compound component pattern. You must wrap all parts in `Alert.Root`. The component automatically handles layout and icon selection based on the `colorPalette`.

```jsx live-dev
const App = () => (
  <Alert.Root colorPalette="info">
    <Alert.Title>Information</Alert.Title>
    <Alert.Description>
      This is a basic alert message notifying you of a change.
    </Alert.Description>
  </Alert.Root>
)
```

## Usage examples

### Color palettes

The `colorPalette` prop determines the color and the accompanying icon. Alert accepts every Nimbus palette. The four severities — `critical`, `warning`, `positive` and `info` — use status glyphs, and `primary` uses a megaphone for announcements. Every other palette, `neutral` included, uses a document icon for a plain notice. An alert without a `colorPalette` shows no icon. Supply your own with `Alert.Icon`, or remove it with `hideIcon`.

```jsx live-dev
const App = () => (
  <Stack direction="column" gap="400">
    <Alert.Root colorPalette="positive">
      <Alert.Title>Positive</Alert.Title>
      <Alert.Description>Operation completed successfully.</Alert.Description>
    </Alert.Root>

    <Alert.Root colorPalette="warning">
      <Alert.Title>Warning</Alert.Title>
      <Alert.Description>Please review your changes.</Alert.Description>
    </Alert.Root>

    <Alert.Root colorPalette="critical">
      <Alert.Title>Critical</Alert.Title>
      <Alert.Description>An error occurred while saving.</Alert.Description>
    </Alert.Root>

    <Alert.Root colorPalette="info">
      <Alert.Title>Info</Alert.Title>
      <Alert.Description>New updates are available.</Alert.Description>
    </Alert.Root>

    <Alert.Root colorPalette="neutral">
      <Alert.Title>Neutral</Alert.Title>
      <Alert.Description>General notice with no severity.</Alert.Description>
    </Alert.Root>

    <Alert.Root colorPalette="primary">
      <Alert.Title>Primary</Alert.Title>
      <Alert.Description>An announcement — a new feature, or news about the product.</Alert.Description>
    </Alert.Root>
  </Stack>
)
```

### Visual variants (emphasis)

The `variant` prop controls emphasis: `outlined` (tinted card), `accent-start` (neutral card with a status-colored bar on the leading edge), and `flat` (no chrome). All three share the same padded box. Omit `variant` for an unstyled alert with no padding, which sits flush with its container.

`accent-start` is close to the treatment `Toast` uses by default. The reading surface and the text stay neutral while the bar, the icon and any buttons in `Alert.Actions` carry the status color, so several of them can sit on one page without it reading as a color chart. The dismiss button stays neutral, since it is chrome rather than an action. The bar follows the reading direction: it moves to the right edge under `dir="rtl"`.

```jsx live-dev
const App = () => (
  <Stack direction="column" gap="400">
    <Alert.Root variant="outlined" colorPalette="info">
      <Alert.Title>Outlined</Alert.Title>
      <Alert.Description>
        Tinted card. Best when the alert needs to stand out against surrounding content.
      </Alert.Description>
    </Alert.Root>

    <Alert.Root variant="accent-start" colorPalette="info">
      <Alert.Title>Accent start</Alert.Title>
      <Alert.Description>
        Neutral card, status color in the bar and the icon only. Close to the look Toast uses.
      </Alert.Description>
    </Alert.Root>

    <Alert.Root variant="flat" colorPalette="info">
      <Alert.Title>Flat</Alert.Title>
      <Alert.Description>
        No chrome. Suitable for dense interfaces or secondary notifications.
      </Alert.Description>
    </Alert.Root>
  </Stack>
)
```

### Layout

Alert has a single arrangement and no `layout` prop: the status icon leads, the title and description stack beside it, actions sit below, and the dismiss button sits on the trailing edge. Anything beyond that is placement and style props — a full-width page banner is the same alert with its corners squared and its padding widened.

```jsx live-dev
const App = () => (
  <Stack direction="column" gap="400">
    <Alert.Root colorPalette="info" variant="outlined">
      <Alert.Title>Default</Alert.Title>
      <Alert.Description>
        Icon on the leading edge, title and description beside it, actions and the dismiss button below.
      </Alert.Description>
    </Alert.Root>

    <Alert.Root
      colorPalette="warning"
      variant="outlined"
      borderRadius="0"
      paddingInline="600"
    >
      <Alert.Title>Full-bleed banner</Alert.Title>
      <Alert.Description>
        Edge-to-edge for page-level messages, built from style props rather than a layout axis.
      </Alert.Description>
    </Alert.Root>
  </Stack>
)
```

For a compact horizontal row with leading media and trailing actions — a settings row, a notification row, an agent confirmation — use `Item` instead. Alert is for status messages that may need announcing.

#### Silent confirmation (agent-confirmation pattern)

`role="group"` + `aria-label` with `hideIcon` produces a confirmation that is not announced as a live region — useful for confirming a user-initiated action (e.g. an agent applying a suggestion) that the user is already watching, where an additional announcement would be redundant.

```jsx live-dev
const App = () => {
  const [applied, setApplied] = useState(true);

  if (!applied) {
    return <Text>Change undone.</Text>;
  }

  return (
    <Alert.Root
      colorPalette="positive"
      role="group"
      aria-label="Suggestion approved"
      hideIcon
    >
      <Alert.Title>Suggestion approved</Alert.Title>
      <Alert.Description>
        Applied the recommended discount to 3 products.
      </Alert.Description>
      <Alert.Actions>
        <Button variant="outline" onPress={() => setApplied(false)}>
          Undo
        </Button>
      </Alert.Actions>
    </Alert.Root>
  );
}
```

### Icon customization

Omit `Alert.Icon` for the automatic status icon (based on `colorPalette`). Provide `Alert.Icon` with any icon to override it, or use `hideIcon` on `Alert.Root` to suppress the icon entirely (it takes precedence over both the automatic icon and an explicit `Alert.Icon`).

```jsx live-dev
const App = () => (
  <Stack direction="column" gap="400">
    <Alert.Root colorPalette="info">
      <Alert.Icon><Icons.StarOutline /></Alert.Icon>
      <Alert.Title>Custom icon</Alert.Title>
      <Alert.Description>Replaces the automatic status icon.</Alert.Description>
    </Alert.Root>

    <Alert.Root colorPalette="info" hideIcon>
      <Alert.Title>No icon</Alert.Title>
      <Alert.Description>hideIcon suppresses the icon entirely.</Alert.Description>
    </Alert.Root>
  </Stack>
)
```

### Flexible composition

The component parts (`Title`, `Description`, `Actions`, `DismissButton`) can be composed as needed. The `Alert.Root` handles the layout regardless of the order in JSX.

**Title only:**

```jsx live-dev
const App = () => (
  <Alert.Root colorPalette="positive">
    <Alert.Title>Success: Item created.</Alert.Title>
  </Alert.Root>
)
```

**Description only:**

```jsx live-dev
const App = () => (
  <Alert.Root colorPalette="info">
    <Alert.Description>
      System maintenance scheduled for tonight at 02:00 UTC.
    </Alert.Description>
  </Alert.Root>
)
```

### Adding actions

Use `Alert.Actions` to group action buttons. These will be positioned correctly within the alert layout.

```jsx live-dev
const App = () => (
  <Alert.Root colorPalette="warning">
    <Alert.Title>Storage Limit Reached</Alert.Title>
    <Alert.Description>
      You have used 95% of your available storage.
    </Alert.Description>
    <Alert.Actions>
      <Stack direction="row" gap="200">
        <Button variant="solid">Upgrade Plan</Button>
        <Button variant="ghost">Dismiss</Button>
      </Stack>
    </Alert.Actions>
  </Alert.Root>
)
```

### Dismissible alerts

Render `Alert.DismissButton` to add a close action. It carries a localized
accessible label and is positioned on the trailing edge for you; pass
`variant`, `size` or any other button prop to customize it.

**You** handle the dismissal itself — Alert has no internal open/closed state.

```jsx live-dev
const App = () => {
  const [isVisible, setIsVisible] = useState(true);

  if (!isVisible) {
    return (
      <Button onPress={() => setIsVisible(true)}>
        Reset Example
      </Button>
    );
  }

  return (
    <Alert.Root colorPalette="info" variant="outlined">
      <Alert.Title>Dismissible Alert</Alert.Title>
      <Alert.Description>
        Click the close button to dismiss this message.
      </Alert.Description>
      <Alert.DismissButton onPress={() => setIsVisible(false)} />
    </Alert.Root>
  );
}
```

## Component requirements

## Accessibility

The `Alert` component has built-in accessibility features:

- **Role**: `role` is a native, overridable prop on `Alert.Root`. The default follows `colorPalette`: `critical` gets `role="alert"` (assertive), every other palette gets `role="status"` — a polite live region that doesn't interrupt the user. For an interrupting message on a non-critical palette, pass `role="alert"` explicitly; to keep a critical alert polite, pass `role="status"`. For silent inline confirmations that shouldn't be announced as a live region at all, pass `role="group"` with an `aria-label`. See the Accessibility tab for the full announcement model, including live-region priming guidance.
- **Icons**: The automatic status icon is decorative and automatically hidden from screen readers to avoid redundancy. A custom `Alert.Icon` is rendered as-is — mark it `aria-hidden` yourself if it's purely decorative, or give it an accessible label if it conveys meaning on its own.
- **Dismiss Button**: `Alert.DismissButton` comes with a default accessible label ("Dismiss") which can be localized or overridden via `aria-label`.

If your use case requires tracking and analytics for this component, it is good practice to add a **persistent**, **unique** id to the component:

```tsx
const PERSISTENT_ID = "example-alert";

export const Example = () => (
  <Alert.Root id={PERSISTENT_ID}>
    <Alert.Title>Notification</Alert.Title>
  </Alert.Root>
);
```

### Composition constraints

The `Alert` component manages its own layout grid. To ensure correct placement:

- Keep sub-components (`Icon`, `Title`, `Description`, `Actions`, `DismissButton`) as direct children of `Alert.Root`. Fragments, conditionals and arrays are fine. An `Alert.Icon` inside a wrapper component or a `memo` is not detected: the automatic icon then renders as well, and `hideIcon` does not remove the custom one.
- Do not wrap sub-components in other elements (like `div` or `Stack`), as these wrappers will be rendered as part of the layout and may break the visual structure.
- You *can* use layout components *inside* `Alert.Actions` or `Alert.Description` to organize content within those slots.
