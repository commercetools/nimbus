## Overview

Use `RadarChart` to compare several measures of one or more series, for example
the skills of two players. Each measure is a spoke around the center, and each
series is a polygon that connects its values on the spokes.

> [!WARNING]\
> **Experimental.** `RadarChart` is experimental in this first release and may
> change in a later version.

`RadarChart` needs two peer dependencies that are not installed with Nimbus:
`recharts` and `react-is`. Install both:

```bash
pnpm add recharts react-is
```

npm and yarn also work (`npm install recharts react-is`,
`yarn add recharts react-is`). Nimbus accepts `recharts` version `^3.10.1` or
newer in the same major version.

A chart is given the rows of data, the field that names each spoke (`xAxisKey`),
the series to draw, and a label and color for each series. It fills the width of
its container and has a default aspect ratio. The look is minimal: a light polar
grid, polygons with a low-opacity fill and a full-color outline, and a tooltip
with the values of one data point.

## Variables

### One series

A chart with one series does not show a legend by default. Set `showLegend` to
show it.

```jsx live
const App = () => {
  const data = [
    { skill: "Speed", alpha: 120, beta: 80 },
    { skill: "Power", alpha: 98, beta: 130 },
    { skill: "Range", alpha: 86, beta: 100 },
    { skill: "Skill", alpha: 99, beta: 90 },
    { skill: "Focus", alpha: 85, beta: 110 },
  ];
  return (
    <RadarChart
      aria-label="Skills of player Alpha"
      data={data}
      xAxisKey="skill"
      series={["alpha"]}
      config={{ alpha: { label: "Alpha", palette: "ctviolet" } }}
    />
  );
};
```

### Several series

With two or more series the legend is always shown. Each series has a `label`
and an optional `palette` in `config`. Each series is a polygon with a
low-opacity fill and a full-color outline, so overlapping polygons stay
readable.

```jsx live
const App = () => {
  const data = [
    { skill: "Speed", alpha: 120, beta: 80 },
    { skill: "Power", alpha: 98, beta: 130 },
    { skill: "Range", alpha: 86, beta: 100 },
    { skill: "Skill", alpha: 99, beta: 90 },
    { skill: "Focus", alpha: 85, beta: 110 },
  ];
  return (
    <RadarChart
      aria-label="Skills by player"
      data={data}
      xAxisKey="skill"
      series={["alpha", "beta"]}
      config={{
        alpha: { label: "Alpha", palette: "ctviolet" },
        beta: { label: "Beta", palette: "orange" },
      }}
    />
  );
};
```

### Grid

The polar grid (rings and spokes) is shown by default. Set `showGrid={false}` to
hide it when the values are easy to read from the tooltip.

```jsx live
const App = () => {
  const data = [
    { skill: "Speed", alpha: 120, beta: 80 },
    { skill: "Power", alpha: 98, beta: 130 },
    { skill: "Range", alpha: 86, beta: 100 },
    { skill: "Skill", alpha: 99, beta: 90 },
    { skill: "Focus", alpha: 85, beta: 110 },
  ];
  return (
    <RadarChart
      aria-label="Skills by player, without grid"
      data={data}
      xAxisKey="skill"
      series={["alpha", "beta"]}
      showGrid={false}
      config={{
        alpha: { label: "Alpha", palette: "ctviolet" },
        beta: { label: "Beta", palette: "orange" },
      }}
    />
  );
};
```

### States

Set `isLoading` to show a placeholder while the data loads. An empty `data`
array shows the text "No data to display".

```jsx live
const App = () => (
  <Stack direction="column" gap="400">
    <RadarChart
      aria-label="Loading chart"
      data={[]}
      xAxisKey="skill"
      series={["alpha"]}
      config={{ alpha: { label: "Alpha" } }}
      isLoading
    />
    <RadarChart
      aria-label="Empty chart"
      data={[]}
      xAxisKey="skill"
      series={["alpha"]}
      config={{ alpha: { label: "Alpha" } }}
    />
  </Stack>
);
```

### Spokes

`xAxisKey` is the data field that names each spoke. Each row of `data` is one
spoke. A polygon needs at least three spokes: with two spokes a series looks
like a line, and with one spoke like a point. Every key in `series` must exist
in `config`; a key that is missing there is skipped.

## Colors

Each series has a color. Choose it with the name of a palette in `config`, for
example `"ctviolet"` or `"orange"`. Only the 23 chart palettes are accepted:
blue, bronze, brown, crimson, ctviolet, cyan, gold, grass, gray, green, indigo,
iris, jade, orange, pink, plum, purple, red, ruby, slate, teal, tomato, violet.

Seven palettes are not available, because their solid color is light and has a
black contrast color: amber, lime, mint, sky, yellow, ctyellow and ctteal.

When a series has no `palette`, it gets the next palette of the default order:
ctviolet, orange, teal, crimson, blue, grass, plum, bronze, cyan, red and slate.
A chart with more than 11 series uses the same order again from the start.

A chart uses the solid color of the palette. Only the lightness changes, and
only as much as needed so the color has at least 3:1 contrast against the `bg`
color of the current color mode. Colors are checked against `bg` only. Place
charts on `bg`. On gray or tinted surfaces, a few palettes can have a contrast a
little below 3:1.

## Guidelines

### Best practices

- Write an `aria-label` that says what the chart shows and for which period.
- Keep the number of series low. The default order has 11 palettes that are easy
  to tell apart; more series reuse colors.
- Use short, clear labels. They appear in the legend and the tooltip.
- Place the chart on the `bg` color so the contrast checks apply.

### When to use

> [!TIP]\
> Use `RadarChart` to compare the profile of a few series over 3 to 8 measures
> that use the same scale.

> [!CAUTION]\
> Do not use `RadarChart` for measures with different scales or units, for fewer
> than 3 measures, or when readers must read exact values (use a bar chart).

## Accessibility

- Every chart needs an `aria-label` that says what the chart shows, for example
  "Skills by player".
- Keyboard: Tab moves focus to the chart. ArrowLeft and ArrowRight move between
  the data points and show the tooltip. Enter hides the tooltip and shows it
  again.
- The tooltip is a live region, so a screen reader announces the values of the
  active data point.
- The legend is always shown for two or more series, so color is never the only
  way to tell series apart. `showLegend` only matters for a chart with one
  series.
- The draw animation is off by default when the person prefers reduced motion.
  Use `isAnimationActive` to set it yourself.
