## Getting started

### Import

```tsx
import { Meter, type MeterRootProps } from "@commercetools/nimbus";
```

### Basic usage

Meter uses a compound pattern. `Meter.Root` holds all data: the `value`, the
range and the format. The parts inside it show that data:

- `Meter.Label`: the visible name of the meter
- `Meter.Value`: the formatted value
- `Meter.Track`: the bar
- `Meter.Legend`: the name and value of each segment (see
  [Multiple segments](#multiple-segments))

Render only the parts you need. The default range is 0 to 100, and the value is
formatted as a percent.

```jsx live-dev
const App = () => (
  <Meter.Root value={40}>
    <Meter.Label>CPU usage</Meter.Label>
    <Meter.Value />
    <Meter.Track />
  </Meter.Root>
);
```

## Usage examples

### Size options

`size` sets the bar thickness: `sm` (4px), `md` (8px, default) and `lg` (12px).
It also sets a matching text style for label, value and legend: `sm` → `xs`,
`md` → `sm`, `lg` → `md`.

```jsx live-dev
const App = () => (
  <Stack direction="column" gap="400">
    <Meter.Root value={60} size="sm">
      <Meter.Label>Small (sm)</Meter.Label>
      <Meter.Value />
      <Meter.Track />
    </Meter.Root>
    <Meter.Root value={60} size="md">
      <Meter.Label>Medium (md)</Meter.Label>
      <Meter.Value />
      <Meter.Track />
    </Meter.Root>
    <Meter.Root value={60} size="lg">
      <Meter.Label>Large (lg)</Meter.Label>
      <Meter.Value />
      <Meter.Track />
    </Meter.Root>
  </Stack>
);
```

### Text style

To change the text, use the `textStyle` style prop. On `Meter.Root` it changes
the text of all parts. On one part it changes only that part, for example a
large value above a thin bar.

```jsx live-dev
const App = () => (
  <Stack direction="column" gap="600">
    <Meter.Root value={60} size="sm" textStyle="md">
      <Meter.Label>Small bar, text style md</Meter.Label>
      <Meter.Value />
      <Meter.Track />
    </Meter.Root>
    <Meter.Root value={96} size="sm">
      <Meter.Label>Catalog completeness</Meter.Label>
      <Meter.Value textStyle="2xl" fontWeight="700" />
      <Meter.Track />
    </Meter.Root>
  </Stack>
);
```

### Layout options

The `layout` prop places the parts. Each part has a fixed place, so you can
write the parts in any order.

- `stacked` (default): label and value on one line above the track, legend
  below the track
- `inline`: label, track and value on one line, legend below

```jsx live-dev
const App = () => (
  <Stack direction="column" gap="600">
    <Meter.Root value={50} layout="stacked">
      <Meter.Label>Stacked (default)</Meter.Label>
      <Meter.Value />
      <Meter.Track />
    </Meter.Root>
    <Meter.Root value={50} layout="inline">
      <Meter.Label>Inline</Meter.Label>
      <Meter.Value />
      <Meter.Track />
    </Meter.Root>
  </Stack>
);
```

Put other content, such as a note below the meter, outside `Meter.Root`. Only
the Meter parts have a place in the layout.

### Bar only

To show only the bar, render `Meter.Track` alone. Without `Meter.Label`, set
`aria-label` on `Meter.Root`, so the meter still has an accessible name.

```jsx live-dev
const App = () => (
  <Meter.Root value={50} aria-label="Disk usage">
    <Meter.Track />
  </Meter.Root>
);
```

> [!TIP]\
> Without `Meter.Value`, show the same value as text near the meter, for example
> in the same table row. Some fill colors have low contrast with the track, so
> the bar alone is hard to read.

### Custom range

Use `minValue` and `maxValue` to measure against a range other than 0-100. The
filled part is always relative to this range.

```jsx live-dev
const App = () => (
  <Meter.Root
    value={35}
    minValue={10}
    maxValue={60}
    formatOptions={{ style: "unit", unit: "celsius" }}
  >
    <Meter.Label>Temperature</Meter.Label>
    <Meter.Value />
    <Meter.Track />
  </Meter.Root>
);
```

### Value formatting

Use `formatOptions` on `Meter.Root` to control how the value is displayed. This
accepts a standard `Intl.NumberFormatOptions` object. The default is
`{ style: "percent" }`. Use `valueLabel` to replace the formatted text with a
fully custom string, for example to show a fraction instead of a percent.

```jsx live-dev
const App = () => (
  <Stack direction="column" gap="400">
    <Meter.Root value={72}>
      <Meter.Label>Default (percent)</Meter.Label>
      <Meter.Value />
      <Meter.Track />
    </Meter.Root>
    <Meter.Root value={50} formatOptions={{ style: "unit", unit: "gigabyte" }}>
      <Meter.Label>Unit</Meter.Label>
      <Meter.Value />
      <Meter.Track />
    </Meter.Root>
    <Meter.Root value={50} valueLabel="50 of 100 GB">
      <Meter.Label>Custom value label</Meter.Label>
      <Meter.Value />
      <Meter.Track />
    </Meter.Root>
  </Stack>
);
```

### Multiple segments

Pass `segments` instead of `value` to show several measured parts inside one
total. `value` and `segments` cannot both be set — the type is a discriminated
union that rejects passing both. Each item in `segments` needs a unique `id`, a
`label`, and a `value` (the amount it contributes).
`Meter.Track` draws the segments in array order, and `Meter.Root` builds one
accessible summary for the whole meter.

Always render `Meter.Legend` with segments. It shows the name and value of each
segment next to its color, so the segments are not told apart by color only.
`Meter.Root` logs a warning in development mode when segments have no legend.

With `segments`, `minValue` is always `0`, so the parts add up to the total,
apart from rounding.

```jsx live-dev
const App = () => (
  <Meter.Root
    formatOptions={{ style: "unit", unit: "gigabyte" }}
    segments={[
      { id: "images", label: "Images", value: 30 },
      { id: "videos", label: "Videos", value: 20 },
    ]}
  >
    <Meter.Label>Storage</Meter.Label>
    <Meter.Value />
    <Meter.Track />
    <Meter.Legend />
  </Meter.Root>
);
```

If the segment values add up to more than the range, they are cut once the track
is full. If a segment has a negative value, it is treated as `0`. In both cases
the legend and the announced text show the amount that is drawn, so they match
the bar. Each value is rounded on its own, so rounded parts can differ slightly
from the total (for example `100%` from three parts of `33%`). Both cases log a
warning in development mode, so keep the total inside the range in production
data. A segment with value `0` draws nothing in the track but still appears in
the legend.

### Segment colors

A segment can set its own `colorPalette`, for example to mark one part as a
warning. A segment without a `colorPalette` gets the next color from a fixed
default sequence (`primary`, `orange`, `teal`, `gold`, `pink`, `brown`,
repeating), so adjacent segments never share a color by default.

```jsx live-dev
const App = () => (
  <Meter.Root
    segments={[
      { id: "ok", label: "Healthy", value: 40, colorPalette: "positive" },
      { id: "warn", label: "Degraded", value: 20, colorPalette: "warning" },
    ]}
  >
    <Meter.Label>System health</Meter.Label>
    <Meter.Value />
    <Meter.Track />
    <Meter.Legend />
  </Meter.Root>
);
```

### Color palettes

The `colorPalette` prop on `Meter.Root` themes the fill of a single-value meter
using the system color tokens. Use a semantic palette, such as `positive`,
`warning`, or `critical`, to communicate a state:

```jsx live-dev
const App = () => (
  <Stack direction="column" gap="400">
    <Meter.Root value={80} colorPalette="primary">
      <Meter.Label>Primary</Meter.Label>
      <Meter.Value />
      <Meter.Track />
    </Meter.Root>
    <Meter.Root value={90} colorPalette="positive">
      <Meter.Label>Healthy</Meter.Label>
      <Meter.Value />
      <Meter.Track />
    </Meter.Root>
    <Meter.Root value={55} colorPalette="warning">
      <Meter.Label>Degraded</Meter.Label>
      <Meter.Value />
      <Meter.Track />
    </Meter.Root>
    <Meter.Root value={15} colorPalette="critical">
      <Meter.Label>Critical</Meter.Label>
      <Meter.Value />
      <Meter.Track />
    </Meter.Root>
  </Stack>
);
```

### Thresholds

With a single `value`, `thresholds` changes the fill color when the value
reaches a threshold. Each threshold has a `from` value and a `colorPalette`. The
threshold with the highest `from` that the value reaches is used; below all
thresholds, the fill uses `colorPalette`. The order in the array does not
matter. Segments have their own colors, so `thresholds` works only with
`value`.

```jsx live-dev
const App = () => {
  const thresholds = [
    { from: 80, colorPalette: "warning" },
    { from: 95, colorPalette: "critical" },
  ];

  return (
    <Stack direction="column" gap="400">
      {[60, 85, 97].map((value) => (
        <Meter.Root key={value} value={value} thresholds={thresholds}>
          <Meter.Label>{`Storage at ${value}%`}</Meter.Label>
          <Meter.Value />
          <Meter.Track />
        </Meter.Root>
      ))}
    </Stack>
  );
};
```

The color is a visual hint only. If the state matters, also say it in words,
for example with `valueLabel="97% – almost full"`.

## Component requirements

### Accessibility

The Meter component handles most accessibility requirements internally, using
React Aria Components' `<Meter>`. `Meter.Root` renders `role="meter"` in the DOM
(React Aria adds a second, fallback role token, `progressbar`, for browsers that
do not support the `meter` role; assistive technology reads this as the `meter`
role).

- **Labeling**: give the meter an accessible name, either with `Meter.Label` or
  with `aria-label` / `aria-labelledby` on `Meter.Root`. If none of these is
  provided, React Aria logs a warning in development mode.
- **Role**: the element has `role="meter"` and exposes `aria-valuemin`,
  `aria-valuemax`, and `aria-valuenow`. In segment mode, `aria-valuenow` is
  the sum of the drawn (clamped) segment values, and `aria-valuetext` announces the total followed
  by every segment's label and value, for example
  `"50 GB (Images: 30 GB, Videos: 20 GB)"`. `Meter.Root` builds this text from
  its data, so it is the same no matter which parts you render.
- **Not interactive**: a meter shows a measured value, not a control. It is
  never focusable and does not respond to keyboard input, so it does not need a
  keyboard interaction pattern.
- **Legend**: `Meter.Legend` is marked `aria-hidden="true"`, because
  `aria-valuetext` already announces the same information. It stays visible for
  sighted users so the color of each segment has a text meaning next to it.

If your use case requires tracking and analytics for this component, it is good
practice to add a **persistent**, **unique** id:

```tsx
const PERSISTENT_ID = "storage-quota-meter";

export const Example = () => (
  <Meter.Root id={PERSISTENT_ID} value={72}>
    <Meter.Label>Storage used</Meter.Label>
    <Meter.Value />
    <Meter.Track />
  </Meter.Root>
);
```

## Common patterns

### Storage quota broken down by category

This example shows a total quota broken into categories, a common use of the
segmented mode. The note below the meter is outside `Meter.Root`.

```jsx live-dev
const App = () => {
  const usage = [
    { id: "images", label: "Images", value: 18 },
    { id: "videos", label: "Videos", value: 34 },
    { id: "documents", label: "Documents", value: 6 },
  ];
  const total = usage.reduce((sum, item) => sum + item.value, 0);

  return (
    <Stack direction="column" gap="200">
      <Meter.Root
        maxValue={100}
        formatOptions={{ style: "unit", unit: "gigabyte" }}
        segments={usage}
      >
        <Meter.Label>Storage</Meter.Label>
        <Meter.Value />
        <Meter.Track />
        <Meter.Legend />
      </Meter.Root>
      <Text fontSize="sm" color="neutral.11">
        {total} GB of 100 GB used
      </Text>
    </Stack>
  );
};
```

### Warning when a quota is nearly full

Use `thresholds` so the color follows the value. Here the fill is `positive`
below 70, `warning` from 70 and `critical` from 90.

```jsx live-dev
const App = () => {
  const [used, setUsed] = useState(72);

  return (
    <Stack direction="column" gap="400">
      <Meter.Root
        value={used}
        colorPalette="positive"
        thresholds={[
          { from: 70, colorPalette: "warning" },
          { from: 90, colorPalette: "critical" },
        ]}
      >
        <Meter.Label>Storage used</Meter.Label>
        <Meter.Value />
        <Meter.Track />
      </Meter.Root>
      <Stack direction="row" gap="200">
        <Button onClick={() => setUsed((v) => Math.max(0, v - 10))}>-10</Button>
        <Button onClick={() => setUsed((v) => Math.min(100, v + 10))}>
          +10
        </Button>
      </Stack>
    </Stack>
  );
};
```
