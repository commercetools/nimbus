## Getting started

> [!WARNING]\
> **Experimental.** `BarChart` is experimental in this first release and may
> change in a later version.

Nimbus installs `recharts` and `react-is` with it. You never import from `recharts`: `BarChart` and the chart types come from `@commercetools/nimbus`.

### Import

```tsx
import { BarChart, type BarChartProps, type ChartConfig } from "@commercetools/nimbus";
```

### Basic usage

`BarChart` takes the rows as `data`, the field for the x axis as `xAxisKey`, the
data keys to draw as `series`, and a `config` that maps each data key to a
`label` and an optional `palette`. `aria-label` is required.

Each key in `series` must exist in `config`. A key that is missing in `config`
is skipped, and a warning is logged in development.

```jsx live-dev
const App = () => {
  const data = [
    { month: "Jan", desktop: 186, mobile: 80 },
    { month: "Feb", desktop: 305, mobile: 200 },
    { month: "Mar", desktop: 237, mobile: 120 },
    { month: "Apr", desktop: 273, mobile: 190 },
    { month: "May", desktop: 209, mobile: 130 },
  ];
  return (
    <BarChart
      aria-label="Visitors per month"
      data={data}
      xAxisKey="month"
      series={["desktop", "mobile"]}
      config={{
        desktop: { label: "Desktop", palette: "ctviolet" },
        mobile: { label: "Mobile", palette: "orange" },
      }}
    />
  );
};
```

## Usage examples

### Colors

Choose the color of a series with a palette name in `config`. Only the 23 chart
palettes are accepted: blue, bronze, brown, crimson, ctviolet, cyan, gold, grass, gray, green, indigo, iris, jade, orange, pink, plum, purple, red, ruby, slate, teal, tomato, violet. The `ChartPalette` type lists them, so
TypeScript reports any other name. The 7 palettes with a black contrast color
(amber, lime, mint, sky, yellow, ctyellow and ctteal) are not available.

Without `palette`, a series gets the next palette of the default order: ctviolet,
orange, teal, crimson, blue, grass, plum, bronze, cyan, red and slate. More than
11 series use the same order again from the start.

A chart uses the solid color of the palette, the same color that Nimbus
components use as their main color. Nimbus verifies these colors with APCA.
Color is never the only way to tell series apart: the legend and the tooltip
name each one.

```tsx
const config: ChartConfig = {
  desktop: { label: "Desktop", palette: "ctviolet" },
  mobile: { label: "Mobile" }, // gets the next palette of the default order
};
```

### Stacked series

Set `stacked` to put the series on top of each other.

```jsx live-dev
const App = () => {
  const data = [
    { month: "Jan", desktop: 186, mobile: 80 },
    { month: "Feb", desktop: 305, mobile: 200 },
    { month: "Mar", desktop: 237, mobile: 120 },
    { month: "Apr", desktop: 273, mobile: 190 },
    { month: "May", desktop: 209, mobile: 130 },
  ];
  return (
    <BarChart
      aria-label="Visitors per month, stacked"
      data={data}
      xAxisKey="month"
      series={["desktop", "mobile"]}
      stacked
      config={{
        desktop: { label: "Desktop", palette: "ctviolet" },
        mobile: { label: "Mobile", palette: "orange" },
      }}
    />
  );
};
```

### Legend

The legend is always shown for two or more series, so color is never the only
signal. For one series, set `showLegend` to show it.

```jsx live-dev
const App = () => {
  const data = [
    { month: "Jan", desktop: 186, mobile: 80 },
    { month: "Feb", desktop: 305, mobile: 200 },
    { month: "Mar", desktop: 237, mobile: 120 },
    { month: "Apr", desktop: 273, mobile: 190 },
    { month: "May", desktop: 209, mobile: 130 },
  ];
  return (
    <BarChart
      aria-label="Desktop visitors per month"
      data={data}
      xAxisKey="month"
      series={["desktop"]}
      showLegend
      config={{ desktop: { label: "Desktop", palette: "teal" } }}
    />
  );
};
```

### Grid and tooltip

`showGrid` (default `true`) shows horizontal grid lines. `showTooltip` (default
`true`) shows the tooltip with the values of the active data point.

```jsx live-dev
const App = () => {
  const data = [
    { month: "Jan", desktop: 186, mobile: 80 },
    { month: "Feb", desktop: 305, mobile: 200 },
    { month: "Mar", desktop: 237, mobile: 120 },
    { month: "Apr", desktop: 273, mobile: 190 },
    { month: "May", desktop: 209, mobile: 130 },
  ];
  return (
    <BarChart
      aria-label="Visitors per month, without grid and tooltip"
      data={data}
      xAxisKey="month"
      series={["desktop", "mobile"]}
      showGrid={false}
      showTooltip={false}
      config={{
        desktop: { label: "Desktop" },
        mobile: { label: "Mobile" },
      }}
    />
  );
};
```

### Loading and empty states

`isLoading` shows a skeleton and sets `aria-busy`. An empty `data` array shows
the text "No data to display" in a status region. In both states the root element
has `role="group"` and the `aria-label`.

```jsx live-dev
const App = () => (
  <Stack direction="column" gap="400">
    <BarChart
      aria-label="Loading chart"
      data={[]}
      xAxisKey="month"
      series={["desktop"]}
      config={{ desktop: { label: "Desktop" } }}
      isLoading
    />
    <BarChart
      aria-label="Empty chart"
      data={[]}
      xAxisKey="month"
      series={["desktop"]}
      config={{ desktop: { label: "Desktop" } }}
    />
  </Stack>
);
```

### Animation

`isAnimationActive` turns the draw animation on or off. When you do not set it,
the animation is off if the person prefers reduced motion, and on otherwise.

### Style props

Chakra style props apply to the root element. Without a size, the chart fills the
width of its container and uses a default aspect ratio.

```jsx live-dev
const App = () => {
  const data = [
    { month: "Jan", desktop: 186, mobile: 80 },
    { month: "Feb", desktop: 305, mobile: 200 },
    { month: "Mar", desktop: 237, mobile: 120 },
    { month: "Apr", desktop: 273, mobile: 190 },
    { month: "May", desktop: 209, mobile: 130 },
  ];
  return (
    <BarChart
      aria-label="Visitors per month"
      data={data}
      xAxisKey="month"
      series={["desktop", "mobile"]}
      maxWidth="600px"
      config={{
        desktop: { label: "Desktop" },
        mobile: { label: "Mobile" },
      }}
    />
  );
};
```

## Component requirements

### Accessibility

`aria-label` is required. Describe what the chart shows, for example "Visitors
per month".

- **Legend**: the legend is always shown for two or more series, so color is
  never the only signal. `showLegend` only matters for one series.
- **Marks**: adjacent bars are separated by a 2 px stroke in the `bg` color, so each bar has a visible edge.
- **Tooltip**: the tooltip is a live region (`role="status"`,
  `aria-live="assertive"`), so a screen reader announces the active data point.
- **Motion**: `isAnimationActive` defaults to off when the person prefers
  reduced motion.

If your use case requires tracking and analytics for this component, it is good
practice to add a **persistent**, **unique** id:

```tsx
const PERSISTENT_ID = "visitors-per-month-chart";

export const Example = () => (
  <BarChart
    id={PERSISTENT_ID}
    aria-label="Visitors per month"
    data={[{ month: "Jan", desktop: 186 }]}
    xAxisKey="month"
    series={["desktop"]}
    config={{ desktop: { label: "Desktop" } }}
  />
);
```

#### Keyboard navigation

- `Tab`: moves focus to the chart.
- `ArrowLeft` and `ArrowRight`: move between the data points and show the
  tooltip.
- `Enter`: hides the tooltip, and shows it again.

## Testing your implementation

These examples demonstrate how to test your implementation when using BarChart
within your application. As the component's internal functionality is already
tested by Nimbus, these patterns help you verify your integration and
application-specific logic.

Recharts needs a measured container to draw the marks, and JSDOM has no layout.
In unit tests, test what your code controls: the legend, the series labels, the
loading state and the empty state. Test the drawn marks in a browser test.
