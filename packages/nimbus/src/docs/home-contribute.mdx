# Contributing to nimbus

Product teams can propose pull requests directly to the nimbus repository.
Please read the [collaboration guidelines](/home/getting-started/collaboration)
before contributing.

Before opening a PR:

1. **Discuss the change first.** Start in Slack or a GitHub Issue. The nimbus
   team can help scope the work, flag potential conflicts with in-progress work,
   and confirm the approach aligns with system conventions.
2. **Align on whether the change belongs in nimbus.** Not every useful component
   is a good fit for the core system. The nimbus team is the final
   decision-maker on what goes into nimbus, and an early conversation avoids
   wasted effort.
3. **Follow nimbus conventions.** Contributions should meet the same standards
   as nimbus-authored code: accessibility, testing, documentation, Figma parity,
   and API consistency. The nimbus team can help contributors understand these
   expectations.

The nimbus team reviews and shepherds contributed PRs. Some contributions may be
accepted as-is; others may be adapted or reimplemented to fit system
conventions. In all cases, the contributing team gets credit and the outcome is
collaborative.

## Communication channels

| Channel                                                                          | When to use                                                                                                 |
| :------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------- |
| [**Nimbus Slack channel**](https://commercetools.slack.com/archives/C0ACFBKAHTM) | Quick questions, exploring whether something exists, early-stage feature discussions, architecture guidance |
| [**GitHub Issues**](https://github.com/commercetools/nimbus/issues)              | Formal bug reports, feature proposals (using the template), design discrepancy reports                      |
| **Jira**                                                                         | Tracking work in progress once a decision has been made                                                     |
