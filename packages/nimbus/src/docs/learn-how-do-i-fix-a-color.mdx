You set a color, for example `color="fg.muted"`, and nothing changes. The text
keeps the color of its parent. The token name does not exist in Nimbus. A style
prop accepts any text, so neither TypeScript nor the browser shows an error. Use
a token name that exists.

```jsx live-dev
import { Stack, Text } from "@commercetools/nimbus";

const App = () => (
  <Stack gap="200">
    <Text color="fg.subtle">fg.subtle exists, so this text is lighter.</Text>
    <Text color="fg.muted">
      fg.muted does not exist, so this text keeps its color.
    </Text>
  </Stack>
);
```

| You wrote    | What is wrong            | Use instead                                         |
| ------------ | ------------------------ | --------------------------------------------------- |
| `fg.muted`   | The token does not exist | `fg.subtle`                                         |
| `bg.muted`   | The token does not exist | A step of a palette, for example `neutral.2`        |
| `neutral.90` | Steps go from 1 to 12    | A step from 1 to 12, for example `neutral.11`       |
| `red.400`    | Steps go from 1 to 12    | `red.4`, or `critical.4` if the color is for errors |

## Check a name

- The [Colors](/foundations/design-tokens/colors) page lists every palette and step.
- In code, `system.token("colors.fg.muted")` returns `undefined` for a name that
  does not exist. See
  [Use tokens in your code](/learn/how-do-i/use-tokens-in-your-code).
- AI agents can look up tokens with the `get_tokens` tool of the Nimbus MCP
  server.

A few props have a strict type, for example `colorPalette` on `Button`. There,
TypeScript shows an error for a wrong name.

## Why it works

Nimbus turns a token name into a CSS variable. A name that is not a token goes
to the browser as it is, for example `color: fg.muted`. That is not valid CSS,
so the browser ignores it. See
[Tokens and colors](/learn/concepts/tokens-and-colors).
