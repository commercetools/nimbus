Two different jobs make up most of the work on a screen.

- **Layout** decides where things go and how much space they take. It covers
  direction, alignment, the space between elements, and width and height.
- **Styling** decides how things look. It covers colors, text, borders and
  shadows.

Nimbus has separate tools for each job.

| Question                               | Job     | Nimbus tool                                          |
| -------------------------------------- | ------- | ---------------------------------------------------- |
| Should these items sit in a row?       | Layout  | `Stack` with `direction`                             |
| How much space is between them?        | Layout  | `gap` with a spacing token, such as `gap="400"`      |
| Should these items form columns?       | Layout  | `SimpleGrid` or `Grid`                               |
| Should this button be filled?          | Styling | `variant="solid"`                                    |
| Which color should this text have?     | Styling | `color="primary.11"` or `colorPalette`               |

Both jobs often appear in the same piece of code. The `Stack` does the layout.
The two buttons do the styling.

```tsx
import { Stack, Button } from "@commercetools/nimbus";

<Stack direction="row" gap="400">
  <Button variant="solid" colorPalette="primary">
    Save
  </Button>
  <Button variant="outline">Cancel</Button>
</Stack>;
```

Both jobs use the same values: [design tokens](/home/design-tokens). A token such
as `400` always means the same space, and `primary.11` always means the same
color. That is why a Nimbus screen stays consistent.
