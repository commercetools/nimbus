To change how a Nimbus component looks, go in this order. First try its
theming props, such as `variant` or `colorPalette`. If none fits, set style
props with tokens on the component, or on one of its parts.

## Theming props

Theming props give a component a look that the design system defines. They are
the first choice, because the look stays the same as on every other Nimbus
screen.

- `variant`: the overall style. Button has `solid`, `subtle`, `outline`,
  `ghost` and `link`.
- `size`: the dimensions. Button has `2xs`, `xs`, `sm`, `md` and `xl`.
- `colorPalette`: the color, as a semantic palette such as `primary` or
  `critical`.
- `textStyle`: a text style for `Text` and `Heading`, such as `body`,
  `caption` or `lg`.

```jsx live-dev
import { Button, Stack, Text } from "@commercetools/nimbus";

const App = () => (
  <Stack gap="300" align="start">
    <Stack direction="row" gap="200">
      <Button variant="solid" colorPalette="primary" size="md">
        Save
      </Button>
      <Button variant="outline" colorPalette="critical" size="xs">
        Delete
      </Button>
    </Stack>
    <Text textStyle="caption">Last changed yesterday</Text>
  </Stack>
);
```

Each component page lists the values that the component accepts.

## Style props

When no theming prop fits, set a style prop on that one element. Style props
are named after CSS properties, such as `padding`, `backgroundColor` and
`borderRadius`. Give them a [token](/learn/concepts/tokens-and-colors), not a
raw value. All style props are listed in [Style props](/home/style-props).

```jsx live-dev
import { Box, Text } from "@commercetools/nimbus";

const App = () => (
  <Box padding="400" backgroundColor="info.2" borderRadius="full">
    <Text color="info.11">A box with style props</Text>
  </Box>
);
```

Style props also work on the parts of a component, such as `Card.Header`. See
[Style one part](/learn/how-do-i/style-one-part).

## States

To style a state, pass style props inside a state prop. The most common state
props are `_hover`, `_focusVisible`, `_pressed`, `_selected` and `_disabled`.
They work on Nimbus components, so you do not need class names or data
attributes for states.

```jsx live-dev
import { Box } from "@commercetools/nimbus";

const App = () => (
  <Box
    padding="400"
    backgroundColor="neutral.2"
    borderRadius="200"
    _hover={{ backgroundColor: "neutral.4" }}
  >
    Move the pointer over this box
  </Box>
);
```

## Screen sizes

A style prop can have a different value for each screen size. See
[Layout](/learn/concepts/layout).

## Common mistakes

- **Styling through class names or data attributes.** Nimbus uses them inside
  its components, but they are not part of the API. They can change in any
  release. Use props and parts instead.
- **Selectors that reach into a component.** A rule such as "every `svg` in this
  component" also changes elements that you did not mean, for example icons
  that you add later. Style the part itself.

## What you cannot change

The look of each variant and size is defined by the design system. You can
choose a variant, but you cannot change what the variant looks like for every
use. Adjust single elements with style props instead.

## When nothing fits

If no token gives the value that you need, use a raw value on that one element
and mark it as a [one-off](/learn/rules):

```jsx live-dev
import { Text } from "@commercetools/nimbus";

const App = () => {
  // nimbus-one-off: the legal text must use the letter spacing from the contract
  const legalLetterSpacing = "0.02em";

  return (
    <Text textStyle="caption" letterSpacing={legalLetterSpacing}>
      Terms and conditions apply.
    </Text>
  );
};
```
