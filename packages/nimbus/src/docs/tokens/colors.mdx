Nimbus colors are built on [Radix Colors](https://www.radix-ui.com/colors).
Every color is a **palette** of 12 steps plus a `contrast` step, and each step
has one job: a background, a border or a text color. Palettes work in light and
dark mode without extra work.

Find a color below, then see [how to use it in code](#use-colors-in-code) or
[how a scale works](#how-a-scale-works).

## Use colors in code

### Palette tokens

Refer to a color by its palette and step. Components take a palette with the
`colorPalette` prop and choose the steps themselves. Because the scales are
interchangeable, you can swap the palette without losing contrast.

```tsx
// A palette and a step
<Box bg="primary.3" color="primary.11" borderColor="primary.7">
  content
</Box>

// A component with another palette
<Button colorPalette="critical" variant="solid">
  Delete
</Button>

// In a recipe, colorPalette stands for the palette the component gets
base: {
  bg: "colorPalette.9",
  color: "colorPalette.contrast",
}
```

### Shorthand tokens

Shorthand tokens cover the most common cases. They map to specific steps of the
`neutral` and status palettes and adapt to light and dark mode. Use them in JSX
props or recipes without naming a palette or a step.

| **Token**           | **Use Case**                       | **Maps to**                         |
| ------------------- | ---------------------------------- | ----------------------------------- |
| `bg`                | Page / container background        | `#fff` (light) · `neutral.1` (dark) |
| `fg`                | Primary text / foreground          | `neutral.12`                        |
| `fg.subtle`         | Secondary text / helper text       | `neutral.11`                        |
| `border`            | Default border color               | `neutral.6`                         |
| `border.muted`      | Subtle border, lower contrast      | `neutral.7`                         |
| `border.subtle`     | Very subtle border / separator     | `neutral.6`                         |
| `border.emphasized` | Emphasized border, higher contrast | `neutral.8`                         |
| `border.inverted`   | Inverted / strong border           | `neutral.9`                         |
| `border.critical`   | Error / destructive borders        | `critical.8`                        |
| `border.warning`    | Warning borders                    | `warning.8`                         |
| `border.positive`   | Success borders                    | `positive.8`                        |
| `border.info`       | Informational borders              | `info.8`                            |

```tsx
// Usage in JSX props
<Box bg="bg" color="fg" borderColor="border.muted">
  content
</Box>

// Usage in recipes
base: {
  bg: "bg",
  color: "fg",
  borderColor: "border",
}
```

## How a scale works

A scale organizes one hue by **contrast** level, from subtle backgrounds to
high-contrast text. The steps fall into four groups, which the palette browser
above also shows:

- **Backgrounds (1–5):** from the app background to selected elements.
- **Borders (6–8):** separators, element borders and focus rings.
- **Solid (9–10):** solid backgrounds and their hover state.
- **Text (11–12):** low-contrast and high-contrast text.

The scales are _interchangeable_: a color like red can be swapped with green
without losing the intended contrast levels, so designs stay adaptable and keep
their visual hierarchy. The same contrast levels also make a separate "dark
mode" design unnecessary, because every scale supports both light and dark
environments.

The table lists each step with its use case and the text colors that work on it.
The colors are from the `primary` palette.

<ColorSteps />

Text steps 11 and 12 pair with background steps 1–5. For text on solid
backgrounds (steps 9 and 10), use the special `contrast` step, which is a black
or white value chosen for readability.

For more details on how the scale is designed, see the
[Radix color scale documentation](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale).

## Accessibility and contrast

Radix builds its palettes to be accessible. It uses
[APCA (Accessible Perceptual Contrast Algorithm)](https://github.com/Myndex/APCA),
a more advanced method for calculating perceived contrast that accounts for
human visual perception more accurately than the traditional WCAG 2.x formula.

> **Note:** Some automated accessibility tools still use the older WCAG 2.x
> synthetic contrast calculation (4.5:1 ratio), which can produce false
> positives for certain color combinations that APCA considers accessible. If
> your tooling flags contrast issues with these pairings, verify the results
> against an APCA-based checker before making changes.
