You want an element that takes people to another page. In Nimbus, use `Link`
with `href`. Give your router to `NimbusProvider` once, and `Link` uses it for
client-side navigation.

```jsx live-dev
import { Link, Text } from "@commercetools/nimbus";

const App = () => (
  <Text>
    Before you start, read the <Link href="/learn/rules">rules</Link>.
  </Text>
);
```

## Connect your router

In a Merchant Center application, the application shell already gives its
router to `NimbusProvider`, so `Link` with `href` works without any setup.

In other apps, pass the `navigate` function of your router to the `router` prop.
This example uses React Router 6. For React Router 5, use
`router={{ navigate: history.push }}` with `useHistory`, as shown on
[Provider and layers](/learn/concepts/provider-and-layers). The
[NimbusProvider](/components/utilities/nimbus-provider) page shows other
routers.

```tsx
import type { ReactNode } from "react";
import { NimbusProvider } from "@commercetools/nimbus";
import { useHref, useNavigate } from "react-router-dom";

export function Providers({ children }: { children: ReactNode }) {
  const navigate = useNavigate();

  return (
    <NimbusProvider router={{ navigate, useHref }}>{children}</NimbusProvider>
  );
}
```

## A link that looks like a button

Use `Button` with `asChild`, and put the link of your router inside it. The
button gives its look to the link.

```tsx
import { Button } from "@commercetools/nimbus";
import { Link as RouterLink } from "react-router-dom";

<Button variant="solid" colorPalette="primary" asChild>
  <RouterLink to="/products/new">Add product</RouterLink>
</Button>;
```

Use this only when the design needs the look of a button. Screen readers then
announce a button, not a link. In all other cases, use `Link`.

## Why it works

`asChild` passes the look and the behavior of a component to its only child. See
[Component structure](/learn/concepts/component-structure) and
[Provider and layers](/learn/concepts/provider-and-layers).
