This page is for designers. It shows which choices Nimbus supports, so that
your design can use them without extra work for developers. A choice that is
not on a component page needs a developer to do extra work. See
[Customize in three steps](/foundations/customize-in-three-steps) for what that
work is.

## The words we use

| Word                   | Meaning                                                                                              |
| ---------------------- | ---------------------------------------------------------------------------------------------------- |
| **Variant**            | A look that a component offers, such as `solid` or `outline` for a button.                           |
| **Size**               | A dimension that a component offers, such as `sm` or `md`.                                           |
| **Color palette**      | A set of colors with 12 steps. In code the prop is `colorPalette`. See [Colors](/foundations/design-tokens/colors). |
| **Supported**          | A variant, a size or a palette that the component offers. This is step 1.                            |
| **One-off**            | A small change that Nimbus does not offer, used in one place, and marked in the code. This is step 2. |
| **Custom composition** | A new layout built from Nimbus parts. This is step 3.                                                |

The words "custom" and "one-off" always mean work outside what Nimbus offers.
A palette that is part of the system is never called "custom".

## Palettes

- **Semantic palettes** have a meaning: `primary`, `neutral`, `info`,
  `positive`, `warning` and `critical`. Use them when the color says something,
  for example `critical` for an error.
- **System palettes**, such as `blue`, `teal`, `mint` or `purple`, have no
  meaning. Use them when the color only separates one item from another.

An app cannot add a palette. A color that is not in a palette needs a one-off.

## Variants and sizes of common components

| Component   | Variants                                                                                                  | Sizes                  |
| ----------- | --------------------------------------------------------------------------------------------------------- | ---------------------- |
| Button      | solid, subtle, outline, ghost, link                                                                        | 2xs, xs, sm, md, xl    |
| Badge       | One look. Choose a palette.                                                                               | 2xs, xs, sm, md        |
| Card        | plain, outlined, elevated, outlined-elevated, muted, outlined-muted, elevated-muted, outlined-elevated-muted | sm, md, lg             |
| Alert       | flat, outlined, accent-start                                                                              | One size               |
| Tabs        | line, rounded, pill                                                                                        | sm, md, lg             |
| Avatar      | subtle, solid                                                                                              | 2xs, xs, md            |
| Text input  | solid, ghost                                                                                               | sm, md                 |
| Switch      | One look.                                                                                                 | sm, md                 |

Most component pages have a Guidelines tab with the full list and rules for use.

## When your design is not on the list

1. **Check the component page.** The variant or size may exist under another
   name.
2. **Change the design to a supported choice.** This costs the least, and it
   keeps your screen like other Nimbus screens.
3. **Ask the Nimbus team.** If many teams need the same thing, Nimbus may add a
   variant. See [Collaboration](/contribute/collaboration).
4. **Mark it in the design file as a one-off or a custom composition.** Your
   product team then owns it.
