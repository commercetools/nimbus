If you follow these eight rules, your screen looks and works like other Nimbus
screens. Each rule links to the concept behind it. To set up Nimbus first, see
the [installation](/home/getting-started/installation).

## 1. Wrap your app in NimbusProvider

Every Nimbus component needs `NimbusProvider` above it. The provider gives the
components their tokens, the color mode and the locale. Put it once, at the
root of your app.

```tsx
import { NimbusProvider } from "@commercetools/nimbus";

export function Root() {
  return (
    <NimbusProvider>
      <App />
    </NimbusProvider>
  );
}
```

See [Provider and layers](/learn/concepts/provider-and-layers).

## 2. Use the components that exist

Before you build a part of the screen yourself, look for it in the
[components](/components) and the [patterns](/patterns). Nimbus components
already work with the keyboard, screen readers and both color modes. A part
that you build yourself must do all of that again.

See [Component structure](/learn/concepts/component-structure).

## 3. Use tokens, not raw values

Give style props a token, such as `400` for space or `critical.2` for a color.
Do not give them raw values such as `16px` or `#fde8e8`. When a color has a
meaning, use a semantic palette: `primary`, `neutral`, `info`, `positive`,
`warning` or `critical`.

```jsx live-dev
import { Box, Text } from "@commercetools/nimbus";

const App = () => (
  <Box padding="400" backgroundColor="critical.2" borderRadius="200">
    <Text color="critical.11">The file could not be saved.</Text>
  </Box>
);
```

See [Tokens and colors](/learn/concepts/tokens-and-colors).

## 4. Try theming props first

Theming props, such as `variant`, `size` and `colorPalette`, give a component a
look that the design system defines. When no theming prop fits, set a style
prop on that one element.

```jsx live-dev
import { Button, Stack } from "@commercetools/nimbus";

const App = () => (
  <Stack direction="row" gap="200">
    <Button variant="outline">Cancel</Button>
    <Button variant="solid" colorPalette="primary">
      Save
    </Button>
  </Stack>
);
```

See [Styling](/learn/concepts/styling).

## 5. Change components only through props and parts

To change a component, use its props and its parts, such as `Card.Header`.
Class names and data attributes inside a component are not part of its API.
They can change in any release, and then your styles stop working.

See [Styling](/learn/concepts/styling) and
[Style one part](/learn/how-do-i/style-one-part).

## 6. Use the Nimbus interaction props

Nimbus components have their own props for events and states. Use `onPress`
instead of `onClick`, and `isDisabled` instead of `disabled`. Most inputs call
`onChange` with the new value, not with an event.

```jsx live-dev
import { useState } from "react";
import { Button, Stack, Text, TextInput } from "@commercetools/nimbus";

const App = () => {
  const [name, setName] = useState("");

  return (
    <Stack gap="200" align="start">
      <TextInput aria-label="Name" value={name} onChange={setName} />
      <Button isDisabled={name === ""} onPress={() => setName("")}>
        Clear
      </Button>
      <Text>Name: {name}</Text>
    </Stack>
  );
};
```

See [Interaction props](/learn/concepts/interaction-props).

## 7. Keep the palettes and conventions as they are

Every app gets the same system palettes, the same 12 steps in each palette and
the same text styles. An app cannot add or change them. This keeps all Nimbus
screens consistent and the contrast accessible in both color modes.

See [Tokens and colors](/learn/concepts/tokens-and-colors).

## 8. Mark every one-off

A one-off is a value or a style that Nimbus does not offer, used in one place.
Sometimes a screen must go to production before Nimbus offers what it needs.
Then write the one-off, and mark it with a comment that starts with
`nimbus-one-off:` and gives the reason. Your team can then search the code for
`nimbus-one-off` and replace each one-off when Nimbus offers a way.

```jsx live-dev
import { Box, Text } from "@commercetools/nimbus";

const App = () => {
  // nimbus-one-off: the banner must be as high as the 72px campaign image
  const bannerHeight = "72px";

  return (
    <Box height={bannerHeight} padding="400" backgroundColor="primary.3">
      <Text>Spring campaign</Text>
    </Box>
  );
};
```

In JSX, write the comment as `{/* nimbus-one-off: reason */}`.
