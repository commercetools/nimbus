## Stacked Bar Chart

<ChartMeta />

A stacked bar chart breaks each category's total into its parts, stacking the
segments in a fixed order so both the total (the full bar) and the mix inside it
are visible at once. Use it to answer "what makes up the whole, category by
category?" — revenue by channel split by customer type, orders per quarter split
by source.

```jsx live
const data = [
  {
    category: "Q1",
    segments: [
      { key: "New", value: 120 },
      { key: "Returning", value: 80 },
      { key: "Wholesale", value: 40 },
    ],
  },
  {
    category: "Q2",
    segments: [
      { key: "New", value: 140 },
      { key: "Returning", value: 96 },
      { key: "Wholesale", value: 52 },
    ],
  },
  {
    category: "Q3",
    segments: [
      { key: "New", value: 118 },
      { key: "Returning", value: 110 },
      { key: "Wholesale", value: 61 },
    ],
  },
  {
    category: "Q4",
    segments: [
      { key: "New", value: 150 },
      { key: "Returning", value: 128 },
      { key: "Wholesale", value: 70 },
    ],
  },
];

const App = () => (
  <ChartThemeProvider mode="light">
    <ResponsiveContainer height={280}>
      {(width, height) => (
        <StackedBarChart
          width={width}
          height={height}
          data={data}
          ariaLabel="Stacked bar chart of orders by quarter, split into New, Returning, and Wholesale"
        />
      )}
    </ResponsiveContainer>
  </ChartThemeProvider>
);
```

## When to use

Reach for a stacked bar chart when the total per category matters _and_ you want
to see what it is composed of. It reads the totals accurately (each bar shares
the zero baseline) and the bottom segment accurately; segments higher in the
stack are harder to compare across categories because they no longer share a
baseline. Keep the number of segments small — three to five keys — or the middle
of the stack turns to noise.

| You want to…                                     | Use instead           |
| ------------------------------------------------ | --------------------- |
| Compare category totals only, one measure each   | `BarChart`            |
| Compare several series side-by-side per category | `GroupedBarChart`     |
| Show composition shifting over a time axis       | `StackedAreaChart`    |
| Compare composition _and_ category size together | `MarimekkoChart`      |
| Show one whole split into shares                 | `DonutChart`          |
| Show diverging sentiment / Likert composition    | `DivergingStackedBar` |

## Getting started

### Import

```tsx
import {
  StackedBarChart,
  ChartThemeProvider,
  ResponsiveContainer,
} from "@commercetools/nimbus-viz";
```

Every chart reads colors from a `ChartThemeProvider` (it calls `useChartTheme()`
and throws without one) and draws into an explicit pixel size supplied by
`ResponsiveContainer`. Mount both once, high in your layout.

## Data shape

`data` is an array of `StackRow` — one bar per row, each row carrying an ordered
set of segments:

```ts
interface StackSegment {
  key: string;
  value: number;
}

interface StackRow {
  category: string;
  segments: StackSegment[];
}
```

```tsx
const data: StackRow[] = [
  {
    category: "Q1",
    segments: [
      { key: "New", value: 120 },
      { key: "Returning", value: 80 },
      { key: "Wholesale", value: 40 },
    ],
  },
  {
    category: "Q2",
    segments: [
      { key: "New", value: 140 },
      { key: "Returning", value: 96 },
      { key: "Wholesale", value: 52 },
    ],
  },
];
```

Contract notes, verifiable from source:

- `category` should be **unique** per row — it is the band-scale domain and the
  React key. Row order is preserved left-to-right.
- Every row should carry the **same segment keys, in the same order**. The
  **first row** defines the legend keys, their order, and their colors; a key
  missing from a later row is treated as `0` in the data table and simply not
  drawn.
- `segments` stack **bottom-to-top in array order** — the first segment sits on
  the baseline and the last gets the rounded top.
- Values are assumed **non-negative**: the value axis is anchored at **0** and
  scaled to the largest total. For signed/diverging composition use
  [`DivergingStackedBar`](/charts/diverging-stacked-bar).

## Chart configuration

### Value formatting

`valueFormat` formats both the value-axis tick labels and the numbers in the
tooltip (the per-category total and each segment value). It defaults to a
compact formatter (`4.2k`); override it for currency, percentages, or units. It
takes precedence over any surrounding `ChartLocaleProvider`.

```jsx live
const data = [
  {
    category: "Q1",
    segments: [
      { key: "New", value: 12000 },
      { key: "Returning", value: 8000 },
      { key: "Wholesale", value: 4000 },
    ],
  },
  {
    category: "Q2",
    segments: [
      { key: "New", value: 14000 },
      { key: "Returning", value: 9600 },
      { key: "Wholesale", value: 5200 },
    ],
  },
];

const App = () => (
  <ChartThemeProvider mode="light">
    <ResponsiveContainer height={280}>
      {(width, height) => (
        <StackedBarChart
          width={width}
          height={height}
          data={data}
          valueFormat={(n) => `$${n.toLocaleString()}`}
        />
      )}
    </ResponsiveContainer>
  </ChartThemeProvider>
);
```

### Overlays (`children`)

Layer-2 annotations (e.g. `ReferenceLine`, `ThresholdBand`, `TargetMarker`) can
be layered over the value axis by passing them as `children`; they render in
plot space against the same scales the bars use.

### Interaction callbacks

`onDatumClick` and `onDatumHover` report the hovered/clicked **row** (the whole
`StackRow`) and its index — use them for drill-down or to drive an external
readout. Hover state is managed internally regardless of whether you pass them.

```tsx
<StackedBarChart
  width={width}
  height={height}
  data={data}
  onDatumClick={({ datum }) => navigate(`/quarter/${datum.category}`)}
/>
```

### Legend, axes & tooltip (automatic)

Not configurable — the chart always draws them. Each distinct segment key gets a
categorical color from the shared entity→color scale, and those key/color pairs
are shown as a **legend** strip. The category axis is a band scale (labels fit
to the band width and truncate when tight); the value axis is a linear scale
from **0** to a "nice" maximum with horizontal gridlines. Hovering a bar dims
the other bars to 0.5 opacity and shows a tooltip with the category, its total,
and every segment value.

### Color & theming

Set the color mode on the provider (`mode="light"` default, or `mode="dark"`).
To follow the app's mode inside a `NimbusProvider`, pass
`mode={coerceColorMode(useColorMode().colorMode)}`. Segments are colored by the
validated `nimbus` categorical palette (contrast + color-vision-deficiency
checks), not ad-hoc CSS colors.

## Responsiveness & performance

Fixed height:

```tsx
<ResponsiveContainer height={280}>
  {(width, height) => (
    <StackedBarChart width={width} height={height} data={data} />
  )}
</ResponsiveContainer>
```

Aspect-ratio height:

```tsx
<ResponsiveContainer aspectRatio={16 / 9} minHeight={200} maxHeight={420}>
  {(width, height) => (
    <StackedBarChart width={width} height={height} data={data} />
  )}
</ResponsiveContainer>
```

`ResponsiveContainer` renders nothing until it observes a positive size, and the
chart returns `null` for a non-positive size — safe inside tabs, drawers, and
initially-hidden containers. Stacked bars are meant for a handful of categories
with a few segments each; there is no downsampling — cap or aggregate categories
and keys upstream.

## Accessibility

Pass an `ariaLabel` that states what the chart shows **and** its takeaway, using
Amy Cesal's formula — `[Chart type] of [data], where [the point]`:

```tsx
<StackedBarChart
  ariaLabel="Stacked bar chart of orders by quarter, where New orders grow every quarter"
  width={width}
  height={height}
  data={data}
/>
```

Don't list individual values in the label; the data-table fallback carries them.

What you get automatically:

- **Labeled graphic.** The SVG is `role="img"` with your `ariaLabel` (a default
  of `"Stacked bar chart of N categories"` is generated if you omit it).
- **Data-table fallback (WCAG 1.1.1).** `StackedBarChart` passes a `table` to
  `ChartContainer`, which renders a visually-hidden `DataTable` (columns
  **Category** plus one column per segment key) into the accessibility tree,
  plus a keyboard "View data as table" toggle that reveals it in place — so the
  numbers are available as text, not just the one-line label.
- **CVD-safe palette + legend.** Segment colors come from the validated chart
  palette, and the always-present legend maps each color back to its key, so
  color is not the only channel identifying a segment.
- **Non-color encoding.** Bar length and baseline position carry the totals and
  the bottom segment; the legend and data table disambiguate the rest.

Your job: pass a meaningful `ariaLabel`, keep the chart in a
`ChartThemeProvider`, and in surrounding copy name the segments rather than "the
blue part". There is no animation, so reduced-motion handling is N/A.

Accessibility checklist:

- [ ] `ariaLabel` states what the chart shows and its takeaway (Cesal formula)
- [ ] Underlying values are available as text (the built-in data-table fallback)
- [ ] Meaning does not depend on color alone (length/position + legend + table)
- [ ] Palette meets contrast + CVD checks (built-in theme; don't override to
      un-validated colors)
- [ ] Surrounding copy names segments/values rather than colors
- [ ] Motion respected where present — N/A, this chart does not animate

## States

`StackedBarChart` renders `null` when `data` is empty or the measured size is
non-positive; it does not draw its own empty, loading, or error message (it does
not forward those `ChartContainer` features). Guard those states upstream and
render your own placeholder when there is no data yet.

## Limitations

- **Non-negative values only.** The baseline is fixed at 0 and segments always
  stack upward; for signed / diverging composition use
  [`DivergingStackedBar`](/charts/diverging-stacked-bar).
- **Vertical only.** There is no horizontal orientation.
- **Row-level interaction.** `onDatumClick` / `onDatumHover` report the whole
  row, not the individual segment under the pointer.
- **No title, subtitle, caption, loading, or error passthrough** —
  `StackedBarChart` forwards only `ariaLabel`, the legend, and the data table to
  `ChartContainer`.
