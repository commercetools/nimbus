## Bar Chart

<ChartMeta />

A bar chart compares a single measure across a handful of categories, drawn from
a shared zero baseline so bar length maps directly to value. Use it to answer
"how do these categories compare in size?" — revenue by channel, orders by
region, tickets by team.

```jsx live
const data = [
  { category: "Web", value: 4200 },
  { category: "Mobile", value: 3100 },
  { category: "Retail", value: 2400 },
  { category: "Partner", value: 1800 },
  { category: "Email", value: 1200 },
];

const App = () => (
  <ChartThemeProvider mode="light">
    <ResponsiveContainer height={280}>
      {(width, height) => (
        <BarChart
          width={width}
          height={height}
          data={data}
          ariaLabel="Bar chart of revenue by channel, where Web leads and Email trails"
        />
      )}
    </ResponsiveContainer>
  </ChartThemeProvider>
);
```

## When to use

Reach for a bar chart when you have one number per category and you want the
comparison to be exact — length on a common baseline is the most accurately read
of all the visual encodings. Keep it to a single measure per category; for
anything richer, move to a sibling below.

| You want to…                                                               | Use instead         |
| -------------------------------------------------------------------------- | ------------------- |
| Compare several series within each category                                | `GroupedBarChart`   |
| Show each bar's internal composition                                       | `StackedBarChart`   |
| Rank many categories with less ink                                         | `LollipopChart`     |
| Highlight which few categories drive the total                             | `ParetoChart`       |
| Show the distribution of one continuous variable                           | `Histogram`         |
| Deviation from baseline **is** the story — sorted by it, symmetric framing | `DivergingBarChart` |

## Getting started

### Import

```tsx
import {
  BarChart,
  ChartThemeProvider,
  ResponsiveContainer,
} from "@commercetools/nimbus-viz";
```

Every chart reads colors from a `ChartThemeProvider` (it calls `useChartTheme()`
and throws without one) and draws into an explicit pixel size supplied by
`ResponsiveContainer`. Mount both once, high in your layout.

## Data shape

`data` is an array of `CategoryDatum` — one row per bar:

```ts
interface CategoryDatum {
  category: string;
  value: number;
}
```

```tsx
const data: CategoryDatum[] = [
  { category: "Web", value: 4200 },
  { category: "Mobile", value: 3100 },
  { category: "Retail", value: 2400 },
];
```

Contract notes, verifiable from source:

- `category` is display text and **need not be unique** — position along the
  band axis comes from row order, not from the label.
- `value` is a plain number and **may be negative**. The value axis always
  includes **0** as its baseline, extended to cover the actual min/max of the
  data — a negative row draws as a bar on the other side of that baseline (below
  it in the vertical orientation, to its left in the horizontal one), not as a
  bar extending upward from zero. See "Color & theming" below for what changes
  visually once a row is negative.
- Row **order** is preserved in the vertical orientation; the horizontal
  (ranked) orientation sorts descending internally.
- To plot your own domain rows instead of `CategoryDatum`, keep the array and
  pass `category` / `value` accessors (see below).

## Chart configuration

### Orientation

`orientation` is `"vertical"` (default) or `"horizontal"`. The horizontal form
is the **ranked** bar chart: rows are sorted by value descending and each bar
gets a direct value label at its end, so it reads as a leaderboard.

```jsx live
const data = [
  { category: "Web", value: 4200 },
  { category: "Mobile", value: 3100 },
  { category: "Retail", value: 2400 },
  { category: "Partner", value: 1800 },
  { category: "Email", value: 1200 },
];

const App = () => (
  <ChartThemeProvider mode="light">
    <ResponsiveContainer height={280}>
      {(width, height) => (
        <BarChart
          width={width}
          height={height}
          data={data}
          orientation="horizontal"
          ariaLabel="Ranked bar chart of revenue by channel"
        />
      )}
    </ResponsiveContainer>
  </ChartThemeProvider>
);
```

### Custom row types

`BarChart` is generic over its row type. Pass `category` / `value` accessors to
feed your own domain objects directly — no reshaping into `CategoryDatum`.

```jsx live
const orders = [
  { channel: "Web", count: 4200 },
  { channel: "Mobile", count: 3100 },
  { channel: "Retail", count: 2400 },
];

const App = () => (
  <ChartThemeProvider mode="light">
    <ResponsiveContainer height={260}>
      {(width, height) => (
        <BarChart
          width={width}
          height={height}
          data={orders}
          category={(d) => d.channel}
          value={(d) => d.count}
          ariaLabel="Bar chart of order count by channel"
        />
      )}
    </ResponsiveContainer>
  </ChartThemeProvider>
);
```

### Value formatting

`valueFormat` formats both the value-axis tick labels and the tooltip value. It
defaults to a compact formatter (`4.2k`); override it for currency, percentages,
or units. It takes precedence over any surrounding `ChartLocaleProvider`.

```jsx live
const data = [
  { category: "Web", value: 4200 },
  { category: "Mobile", value: 3100 },
  { category: "Retail", value: 2400 },
];

const App = () => (
  <ChartThemeProvider mode="light">
    <ResponsiveContainer height={260}>
      {(width, height) => (
        <BarChart
          width={width}
          height={height}
          data={data}
          valueFormat={(n) => `$${n.toLocaleString()}`}
        />
      )}
    </ResponsiveContainer>
  </ChartThemeProvider>
);
```

### Axes, scales & tooltip (automatic)

Not configurable — the chart always draws them. The category axis is a band
scale (labels are fit to the available band width and truncated when tight); the
value-axis domain always includes 0 — from 0 to the "nice" maximum when every
row is non-negative, extended below 0 to the "nice" minimum too when any row is
negative — with horizontal gridlines. Hovering a bar dims the others to 0.4
opacity and shows a small tooltip with the category and formatted value. There
is no legend; see "Color & theming" for how bars are colored, with or without a
legend.

### Value-axis scale

`yScale` picks the value-axis scale kind: `"linear"` (default, unchanged),
`"symlog"`, or `"log"`. `"symlog"` tolerates zero/negative values and compresses
a long tail (revenue, SKU counts) so a few outliers don't flatten the rest of
the bars — the safe toggle over this chart's always-crosses-zero domain. `"log"`
needs a strictly positive domain, which this chart's domain never is (it always
spans down to at least 0), so `yScale="log"` falls back to `"linear"` with a
one-time console warning rather than a degenerate axis; use `"symlog"` instead.

```jsx live
const App = () => (
  <ChartThemeProvider>
    <ResponsiveContainer height={220}>
      {(width, height) => (
        <BarChart
          width={width}
          height={height}
          data={[
            { category: "A", value: 5 },
            { category: "B", value: 50 },
            { category: "C", value: 5000 },
          ]}
          yScale="symlog"
        />
      )}
    </ResponsiveContainer>
  </ChartThemeProvider>
);
```

### Overlays (`children`)

Layer-2 annotations (e.g. `ReferenceLine`, `TargetMarker`) can be layered over
the value axis by passing them as `children`, in **either** orientation.
Overlays that know the difference between the value axis and the position axis
(`ReferenceLine`, `ThresholdBand`) draw correctly in both without any prop
change on the overlay itself — the horizontal (ranked) orientation publishes
`ChartScales.orientation: "horizontal"` (value on x instead of y), which those
overlays read to flip which screen direction they draw in.

```jsx live
const App = () => (
  <ChartThemeProvider mode="light">
    <ResponsiveContainer height={280}>
      {(width, height) => (
        <BarChart
          width={width}
          height={height}
          data={[
            { category: "Web", value: 4200 },
            { category: "Mobile", value: 3100 },
            { category: "Retail", value: 2400 },
          ]}
          orientation="horizontal"
        >
          <ReferenceLine value={3500} label="Target" variant="accent" />
        </BarChart>
      )}
    </ResponsiveContainer>
  </ChartThemeProvider>
);
```

### Interaction callbacks

`onDatumClick` and `onDatumHover` report the datum and its index; use them for
drill-down or to drive external readouts. Hover state is managed internally
regardless.

```tsx
<BarChart
  width={width}
  height={height}
  data={data}
  onDatumClick={({ datum }) => navigate(`/channel/${datum.category}`)}
/>
```

### Color & theming

Set the color mode on the provider (`mode="light"` default, or `mode="dark"`).
To follow the app's mode inside a `NimbusProvider`, pass
`mode={coerceColorMode(useColorMode().colorMode)}`.

Bar color is automatic, not a prop, and depends on the data:

- **Every row non-negative** (the common case): all bars use the single,
  validated chart accent hue. Color carries no meaning here — the category axis
  distinguishes bars, not color — matching every other pure-magnitude chart in
  the "Categorical magnitude" family.
- **Any row negative**: every bar switches to the theme's `positive`/ `negative`
  valence colors, per row, by sign. This is automatic for the whole chart, not
  per-bar-configurable, and not a mix of the two schemes — one negative row
  recolors every bar in the chart, so a reader can't mistake a plain-accent bar
  for "definitely positive."

## Responsiveness & performance

Fixed height:

```tsx
<ResponsiveContainer height={280}>
  {(width, height) => <BarChart width={width} height={height} data={data} />}
</ResponsiveContainer>
```

Aspect-ratio height:

```tsx
<ResponsiveContainer aspectRatio={16 / 9} minHeight={200} maxHeight={420}>
  {(width, height) => <BarChart width={width} height={height} data={data} />}
</ResponsiveContainer>
```

`ResponsiveContainer` renders nothing until it observes a positive size, and the
chart returns `null` for a non-positive size — safe inside tabs, drawers, and
initially-hidden containers. Bar charts are meant for a handful of categories
(they stop being legible past ~20–30 bars); there is no downsampling — cap or
aggregate categories upstream.

## Accessibility

Pass an `ariaLabel` that states what the chart shows **and** its takeaway, using
Amy Cesal's formula — `[Chart type] of [data], where [the point]`:

```tsx
<BarChart
  ariaLabel="Bar chart of revenue by channel, where Web leads and Email trails"
  width={width}
  height={height}
  data={data}
/>
```

Don't list individual values in the label; the data-table fallback carries them.

What you get automatically:

- **Labeled graphic.** The SVG's `role` is `"graphics-document"` (the WAI-ARIA
  Graphics Module container role — not the library's usual `"img"`, which by
  definition disallows focusable descendants) with your `ariaLabel` (a default
  of `"Bar chart of N categories"` is generated if you omit it).
- **Keyboard-operable bars.** Each bar is a real Tab stop: one bar carries
  `role="button"`, an `aria-label` of `"{category}: {formatted value}"`, and
  `tabIndex={0}` at a time (roving tabindex — the rest are `-1`, so Tab never
  has to step through every bar to leave the chart). ArrowRight/ArrowLeft
  (vertical) or ArrowDown/ArrowUp (horizontal) move the focused bar; focusing
  one reports it through `onDatumHover`, driving the same tooltip a mouse hover
  would; Enter/Space activate `onDatumClick`; Escape blurs, dismissing the
  tooltip without losing the roving position.
- **Data-table fallback (WCAG 1.1.1).** `BarChart` passes a `table` to
  `ChartContainer`, which renders a visually-hidden `DataTable` (columns
  **Category**, **Value**) into the accessibility tree, plus a keyboard "View
  data as table" toggle that reveals it in place — so the numbers are available
  as text, not just the one-line label. It sits in Tab order after every bar.
- **CVD-safe palette.** The accent comes from the validated chart theme
  (contrast + color-vision-deficiency checks), not an ad-hoc color.
- **Non-color encoding.** Direction from the zero baseline (up/right vs.
  down/left) always carries sign, independent of color; a negative row's
  automatic recolor to the theme's `negative` role reinforces that, it doesn't
  carry it alone. With no negative rows, color is a single hue and isn't
  load-bearing at all.

Your job: pass a meaningful `ariaLabel`, keep the chart in a
`ChartThemeProvider`, and in surrounding copy name the categories/values rather
than "the tall bar". There is no animation, so reduced-motion handling is N/A.

Accessibility checklist:

- [ ] `ariaLabel` states what the chart shows and its takeaway (Cesal formula)
- [ ] Underlying values are available as text (the built-in data-table fallback)
- [ ] Meaning does not depend on color alone (length/position carry it here)
- [ ] Palette meets contrast + CVD checks (built-in theme; don't override to
      un-validated colors)
- [ ] Surrounding copy names categories/values rather than colors
- [ ] Motion respected where present — N/A, this chart does not animate
- [ ] Marks are keyboard-operable — Tab, arrow keys, Enter/Space, Escape (built
      in, no configuration needed)

## States

`BarChart` renders `null` when `data` is empty or the measured size is
non-positive; it does not draw its own empty, loading, or error message (it does
not forward those `ChartContainer` features). Guard those states upstream and
render your own placeholder when there is no data yet.

## Limitations

- **One measure per category.** No grouped or stacked series — use
  [`GroupedBarChart`](/charts/grouped-bar-chart) or
  [`StackedBarChart`](/charts/stacked-bar-chart).
- **No legend, title, caption, loading, or error passthrough** — `BarChart`
  forwards only `ariaLabel` and the data table to `ChartContainer`.
- **Not every overlay is orientation-aware yet.** `ReferenceLine` and
  `ThresholdBand` draw correctly in both orientations; the rest of `overlays/`
  (`NowLine`, `TargetMarker`, `TrendLine`, `ConfidenceBand`, `BenchmarkSeries`,
  `Annotation`, `EventMarkers`, `ErrorBars`) still assume the value axis is y —
  composing one of those on the horizontal orientation draws it as if the chart
  were still vertical.
